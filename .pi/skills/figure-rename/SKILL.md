# figure-rename

このリポジトリの `figure_rename.py`（`uv run` で動く単一ファイルの Python）を呼び出すラッパです。以下の `<repo>` はこのリポジトリを clone した場所に読み替えてください。モデル名は環境変数 `FIGURE_RENAME_MODEL`、トンネル先の SSH ホストは `FIGURE_RENAME_HOSTS`（カンマ区切り）で指定しておきます。設計は `docs/adr/0001-figure-rename-design.md` と `docs/adr/0002-category-in-name.md` を参照してください。

## 命名規則

`YYYYMMDD_NN_<分類>_画像の内容.ext`

- **YYYYMMDD**: EXIF の撮影日。無ければファイルの更新日時（mtime）
- **NN**: フォルダ × 日付ごとに 01 から、撮影時刻順に振る。整形済みのファイル（`YYYYMMDD_NN_…`）は飛ばし、その続きから振る。100 枚を超えたら 3 桁
- **分類**: `プレゼン`（スライドの撮影・資料のスクショ） / `展示`（ブースの実物・製品・基板・展示ポスター） / `食事`（料理・飲み物・ケータリング） / `その他`（判別できないもの）。dry-run 出力に内訳が出る
- **画像の内容**: モデルが付ける日本語 20 文字程度の名前。画像内に見出しがあればそれを優先し、無ければ「主題＋図の種類」。技術用語は原語のまま。NFC に正規化する
- **ext**: 元の拡張子を小文字にしたもの

## 手順

1. ユーザーの依頼から対象のフォルダかファイルを特定する。サブフォルダも対象にする場合だけ `-r` を付ける。
   - HEIC/HEIF が混ざっていたら、`--convert` を付けるかどうかユーザーに聞く（付けないと拡張子は `.heic` のまま）
2. **dry-run** を実行する（改名はしない）。
   ```bash
   <repo>/figure_rename.py "<フォルダまたはファイル>" [...]
   ```
   - SSH トンネルはスクリプトが自動で張り、終了時に閉じる。モデルが loaded のホストを優先する
   - 初回はモデルの読み込みで数分かかることがある。タイムアウト値は十分に長くする（目安: 10 分）
3. 出力された改名案（`元の名前 → 新しい名前`）を**表にしてユーザーに見せ、承認を得る**。
   - `⚠ Obsidian vault` の警告が出ていたら、「ノート内の `![[…]]` リンクが切れる」ことを必ず伝えて確認する。リンクは書き換えない
   - `(日付は mtime)` の行は、EXIF が無く更新日時を使ったことを示す。必要なら伝える
4. ユーザーが名前の修正を求めたら、`--set` を付けて dry-run をやり直す（解析結果はキャッシュされるので、モデルは呼ばれない）。分類も `展示:` の接頭辞で変えられる。
   ```bash
   <repo>/figure_rename.py "<フォルダ>" --set "IMG_0001.JPG=売上推移グラフ" --set "IMG_0002.JPG=展示:ブースの実物"
   ```
   - 分類だけ変えたいときは `--set "IMG_0002.JPG=食事:"` より plan の `category` 編集か、`--set "IMG_0002.JPG=食事:タイトル"` を使う
   - 分類を増やした後は、該当ファイルを引数で渡して `--refresh` する（全件の再解析は 15 分かかる）
     ```bash
     <repo>/figure_rename.py "<フォルダ>/IMG_1145.JPG" "<フォルダ>/IMG_1146.JPG" --refresh
     ```
5. 承認を得たら、同じ引数（`--set`、`--convert` も含む）に `--apply` を付けて実行する。
6. 改名した件数と結果をユーザーに報告する。

元に戻したいと言われたら、次を実行する。直前の `--apply` 1 回分を戻す。`--convert` していた場合は、書き出した JPEG を消して `.heic-original/` から元の HEIC を戻す。

```bash
<repo>/figure_rename.py "<フォルダ>" --undo
```

## オプション

| オプション | 用途 |
| :--- | :--- |
| `--apply` | 実際に改名する（無ければ dry-run） |
| `--convert` | HEIC/HEIF を JPEG（quality 95・EXIF 保持）に変換する。元ファイルは `.heic-original/` に退避 |
| `--undo` | 直前の `--apply` を元に戻す |
| `-r`, `--recursive` | サブフォルダも対象にする |
| `--set "元=新"` | 改名案を手で指定する（複数可） |
| `--refresh` | キャッシュを無視して解析し直す |
| `--host H` | トンネルを張る SSH ホスト（複数可。既定は `FIGURE_RENAME_HOSTS`） |
| `--model M` | モデル名（既定は `FIGURE_RENAME_MODEL`） |
| `--port N` | ローカル側のポート（既定 8000） |
| `-j N` | 同時に送るリクエスト数（既定 2。共有サーバーなら上限の半分程度にとどめる） |

## 作られるファイル（対象フォルダ内）

- `.figure-rename-plan.json`: 解析結果のキャッシュと改名案。`entries.<元ファイル名>.title` で名前、`.category` で分類（`プレゼン` / `展示` / `食事` / `その他`）を直せる
- `.figure-rename-log.jsonl`: 改名の記録（`--undo` が使う）
- `.heic-original/`: `--convert` で退避した元の HEIC。不要になったら消してよい（`--undo` はこれが残っていることを前提にする）

## うまくいかないとき

| 症状 | 原因と対処 |
| :--- | :--- |
| `localhost:8000 は <モデル> 以外の用途で使われています` | 別のトンネルかサーバーが 8000 番を使っている。`--port 18000` などで回避する |
| `<モデル> を提供しているホストにつながりません` | VPN や SSH 鍵を確認する（`ssh <host> true`）。ユーザーに伝えて止める。sudo は実行しない |
| `解析に失敗した N 件` | もう一度実行すれば、失敗した分だけ解析する |
| 名前が的外れ | `--set` で直すか、`--refresh` で解析し直す |
| 分類が的外れ | `--set "元=展示:タイトル"` か、plan の `entries.<元ファイル名>.category` を直す |
| `HTTP Error 502: Bad Gateway` | モデルが JSON を返せなかったケースは自動で `response_format` なしで再試行する。それでも失敗するなら再実行 |
| `uv: command not found` | `brew install uv` をユーザーに案内する |
