# 0001. figure-rename の設計

- 日付: 2026-10-14
- 状態: 採用

## 背景

スクリーンショット・スライドの撮影画像・図などのファイル名を `YYYYMMDD_NN_画像の内容.ext` に揃えたい。「画像の内容」は画像を解析して決める。解析には、GPU サーバー上の vLLM / llama-swap などが OpenAI 互換 API で提供する画像入力対応モデルを、`ssh -L 8000:localhost:8000` 越しに使う。サーバーは共有で、同時リクエスト数に上限がある（想定は 4）。pi-agent から呼べるスキルとして提供する。

## 決定

### 1. 日付 `YYYYMMDD` = 撮影日。無ければ mtime

EXIF `DateTimeOriginal`（無ければ `DateTime`）を使い、どちらも無ければファイルの更新日時（mtime）を使う。

- 理由: スクショは EXIF を持たないことが多いが、mtime でほぼ正しい日付になる。実行日にすると、過去の画像をまとめて整理したときに日付が意味を失う。

### 2. 連番 `NN` = フォルダ × 日付ごとに 01 から、撮影時刻順

- 同じフォルダに整形済み（`YYYYMMDD_NN_…`）のファイルがあれば、それは再解析も改名もしない。連番はその最大値の続きから振る。
- 99 枚までは 2 桁固定。超えた分は 3 桁にする。
- 理由: 日付と連番の組で 1 枚が一意に決まり、ファイル名でソートすれば時系列に並ぶ。また、何度実行しても結果が変わらない（冪等）。

### 3. 「画像の内容」= 日本語・20 文字程度まで

- 製品名・技術用語は原語のまま残す。
- ファイル名に使えない文字・扱いにくい文字（`/ \ : * ? " < > |`、空白、制御文字）は除去するか `-` に置き換える。
- Unicode は NFC に正規化する。拡張子は元のまま小文字にする。
- 理由: Finder や Obsidian では日本語のほうが内容をつかみやすい。NFC にするのは、macOS の NFD 由来で濁点が分離するのを防ぐため。

### 4. 実装 = `uv run` で動く単一ファイルの Python ＋ 薄い SKILL.md

- `figure_rename.py`（PEP 723 のインラインで依存を宣言: Pillow, pillow-heif）が、EXIF の読み取り・モデルの呼び出し・採番・改名をすべて行う。
- 送信前に長辺 1568px へ縮小し、JPEG にして base64 化する。HEIC にも対応する。
- 理由: 採番・スキップ・正規化・衝突回避は決定的に処理したい。また、pi-agent 側のモデルが画像を読めるかどうかに依存しない。`md-to-pdf` と同じ「スクリプト＋ラッパのスキル」の構成でもある。

### 5. SSH トンネルはスクリプトが自動で管理する

1. `localhost:<port>/v1/models` にモデルがあれば、既存のトンネルをそのまま使う（自分では閉じない）。
2. 無ければ、各ホストで `ssh <host> curl localhost:8000/v1/models` を実行し、モデルが `loaded` のホストを優先する。同じ状態なら指定順にする。
3. `ssh -N -o ExitOnForwardFailure=yes -L <port>:localhost:8000 <host>` を起動し、終了時に閉じる。接続できないか 5xx が返ったら、もう一方のホストに切り替える。
4. `localhost:<port>` がモデル以外に使われていたら、エラーで止める（別のポートへ勝手に逃がさない）。
5. ホストは `--host` か環境変数 `FIGURE_RENAME_HOSTS`、モデル名は `--model` か `FIGURE_RENAME_MODEL` で指定する。ポートは `--port`。ホスト名・モデル名はスクリプトに埋め込まない（環境ごとに違うため）。

- 理由: unloaded のホストに投げると、llama-swap がモデルを切り替えるあいだ数分待たされるうえ、そのホストを使っている他の人にも影響する。

### 6. 既定は dry-run。`--apply` で改名し、`--undo` で戻せる

- dry-run では改名案を表示し、`.figure-rename-plan.json` にキャッシュする。`--apply` はこの plan を再利用する（モデルを 2 回呼ばないため、確認した案と実際の改名が一致する）。plan 作成後に対象ファイルが変わっていたら、再解析する。
- 名前は個別に上書きできる。方法は `--set "元ファイル名=新しい内容"` と、plan の `title` の直接編集の 2 つ。
- `--apply` の結果は `.figure-rename-log.jsonl` に追記する。`--undo` で直前の実行分を元に戻せる。
- スキルの手順: dry-run の結果をユーザーに見せ、承認を得てから `--apply` を実行する。
- 理由: 名前は LLM の出力なので、的外れになることがある。

### 7. 対象と範囲

- 引数にフォルダかファイルを複数指定できる。フォルダはサブフォルダに降りない（`--recursive` で降りる）。
- 対象の拡張子: `png jpg jpeg heic heif webp gif`。隠しファイルは除外する。
- 改名は同じフォルダ内で行い、ファイルを移動しない。
- 対象が Obsidian vault（祖先に `.obsidian/` がある）の中なら警告を出す。スクリプトはノート内のリンク（`![[…]]`）を書き換えない。スキルの手順では、この場合に必ずユーザーへ確認する。

### 8. モデルへの依頼内容

- 画像内に見出し（スライドのタイトル、キャプション、ウィンドウ名など）が読めれば、それを優先して使う。無ければ「主題＋図の種類」（構成図／グラフ／表／スクショ／写真／フロー図 など）で名付ける。
- 応答は JSON `{"title","reason"}` で返させる。応答から JSON を抜き出す処理も入れる。
- 呼び出しの設定:
  - `temperature: 0`
  - `chat_template_kwargs.enable_thinking: false`
  - 同時に送るのは既定で 2 件（`--jobs`）。共有サーバーなので、上限 4 件の半分にとどめる
  - タイムアウトは 240 秒
- 20 文字を超えたら、1 回だけ短くするよう再依頼する。それでも長ければ 20 文字で切る。

### 9. リポジトリ

- ADR は `docs/adr/` に置く。

## 影響

- 依存は `uv` と、リモートのモデルを使う場合の `ssh` だけ。exiftool は不要。
- モデルがどのホストでも使えないときは、改名せずにエラーで終わる。
- Obsidian の添付画像を改名すると、ノートのリンクは手で直す必要がある。
