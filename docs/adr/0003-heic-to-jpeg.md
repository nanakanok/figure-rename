# 0003. HEIC → JPEG 変換を改名と同じ操作に組み込む

- 日付: 2026-10-15
- 状態: 採用
- 関連: 0001, 0002

## 背景

iPhone で撮った画像が `IMG_xxxx.HEIC` で 82 枚追加された。Obsidian や Web で扱いやすいよう JPEG にしたい。改名はすでに `figure_rename.py` が行っているので、変換だけ別ツールでやると「変換 → 改名」の 2 手順になり、間に元ファイル名が消える時間ができる。

## 決定

### 1. `--convert` で「変換しながら改名」する

`--convert` を付けると HEIC/HEIF の拡張子は `.jpg` になり、`im.save(dst, "JPEG", quality=95)` で**最終名で直接書き出す**。中間ファイルを作らない。

- 理由: 変換と改名が 1 回の `--apply` で完結する。dry-run ではファイルに触らず、改名案に `(HEIC→JPEG)` と表示するだけ。
- 影響: 0001 の「拡張子は元のまま小文字」は `--convert` を付けたときだけ上書きされる。既定の挙動は変えない。

### 2. EXIF は保持し、回転はピクセルに焼き込む

`ImageOps.exif_transpose()` 後に `exif=` で書き出す。`DateTimeOriginal` が残るため日付 `YYYYMMDD` は EXIF から取れる（mtime に落ちない）。orientation は 1 になる。

- 理由: 0001 の採番の根拠が撮影日だから、EXIF を失うと日付が壊れる。

### 3. 元の HEIC は同じフォルダから消さず `.heic-original/` に退避する

`figure/.heic-original/IMG_xxxx.HEIC` へ移す。隠しフォルダなので 0001 の対象収集（隠しファイル・隠しフォルダ除外）にかからず、重複改名は起きない。

- 理由: 変換は不可逆（HEIF → JPEG は再符号化）。`--undo` は「JPEG を削除 → 退避した HEIC を元名に戻す」で完全に戻せる。Finder からも見えない。
- 影響: 容量が一時的に二重になる（HEIC 201MB + JPEG 約 450MB）。不要になったら `.heic-original/` を消せばよい。

### 4. quality は 95、リサイズはしない

原寸（例: 5712×4284）のまま。解析用に長辺 1568px へ縮小する処理とは別物で、保存するファイルは元サイズを保つ。

- 理由: 元画像の情報を捨てない。Web 用に軽くしたい需要が出たら、そのときにオプションで足す。

## 影響

- `--undo` は変換を伴う実行でも戻せる（`convert: true` と `original` をログに記録する）。
- 既に整形済みの `.heic`（`20261013_01_展示_xxx.heic`）は 0001 のスキップ規則で変換されない。
- 動画（`.MOV`）は対象外のまま。
