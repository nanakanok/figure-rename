# 0002. ファイル名に分類（プレゼン / 展示 / その他）を入れる

- 日付: 2026-10-14
- 状態: 採用
- 関連: 0001

## 背景

カンファレンスで撮った画像が `figure/` に混在している。スライドの撮影・資料のスクショ（プレゼン）と、ブースで撮った実物・実演（展示）を、ファイル名を見た時点で区別したい。

## 決定

### 1. 命名規則を `YYYYMMDD_NN_<分類>_画像の内容.ext` にする

`NN` の直後に分類を入れる。日付と連番の並び順は 0001 のまま変えない（`YYYYMMDD`。依頼では `YYYYDDMM` と書かれたが、既存の規則と Finder のソート順を保つため `YYYYMMDD` のまま）。

- 理由: `ls` のソートで日付 → 連番 → 分類の順に並ぶ。連番の後ろに置いたので、0001 の採番ロジック（フォルダ × 日付で 01 から）はそのまま使える。

### 2. 分類は 4 択。モデルに `category` として返させる

- `プレゼン`: 会議・セッションのプレゼン資料。スクリーンに写したスライド、スライドのスクショ、資料の画面
- `展示`: 展示会・ブースでの実物や実演。製品・機器・基板・ラック・モジュールなどの写真、展示ポスター
- `食事`: 食べ物・飲み物。会場内のケータリング、料理、弁当、コーヒー
- `その他`: 上記に当てはまらないもの（人物、ブレて判別できない写真など）

`その他` を置いたのは、分類に収まらない画像（ブレ写真など）が無理にどれかへ入って分類の意味が薄れるのを防ぐため。`食事` は当初 `その他` の一部だったが、「会場の食事は別枠で残したい」という要望で独立させた。モデルが別の語（「スライド」「ブース」など）を返しても `normalize_category()` で 4 択に寄せる。

### 3. 分類は 1 回のリクエストでタイトルと一緒に返す

`{"title", "category", "reason"}` を 1 回の呼び出しで返させる。分類だけの 2 回目のパスは作らない。

- 理由: モデルは共有サーバー（同時 4 件）で動いており、リクエスト数を倍にしたくない。
- 影響: 分類を追加した時点でキャッシュの形式が変わるため、`cache_hit()` が `category` を要求し、既存の 418 枚は再解析になる（1 回だけ）。

### 4. 手動修正は `--set "元=展示:タイトル"` と plan の `category` 編集

`--set` の値が分類名（`プレゼン:` / `展示:` / `食事:` / `その他:`）で始まる場合、そこだけ分類として取り、残りをタイトルにする。分類だけ直したいときは `.figure-rename-plan.json` の `entries.<元ファイル名>.category` を編集する。

### 5. 分類を増やしたときは、影響を受けるファイルだけ `--refresh` する

`CATEGORIES` を増やしても、既存キャッシュの `category` は有効なままなので再解析対象にならない。分類し直しが必要なのは `--refresh figure/IMG_1145.JPG figure/IMG_1146.JPG` のように該当ファイルを引数で渡して部分的にやり直す（全 418 枚をやり直すと 15 分かかる）。

## 影響

- 既存の整形済みファイル（`YYYYMMDD_NN_タイトル`）は再解析も改名もしない。分類が入った名前には統一されない。
- 名前の長さはタイトル 20 字 + 分類 2〜6 字。ファイル名全体では 40 字程度に収まる。
